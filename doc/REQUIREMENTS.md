# 算法题编程智能体：需求说明

## 项目目标

本项目面向算法编程题。用户输入自然语言题目以及测试输入、期望输出，系统调用大语言模型在本地编写 Python 题解、执行测试、根据失败结果迭代修改，并在测试通过后给出代码评审。

项目重点不是单次生成答案，而是实现下面的自主闭环：

```text
题目 + 测试输入输出
    -> 模型决定 Bash 动作
    -> 本地环境执行
    -> 结果反馈给模型
    -> 修改并重新测试
    -> 测试通过
    -> Reviewer
```

## 测试用例来源

用户可以选择：

1. 手工填写一组或多组完整的标准输入与期望输出；
2. 将题目交给所选大语言模型，由模型生成测试输入与期望输出，用户可在运行前修改。

两种来源最终都转换为统一的 `test_cases.json`。这份文件同时用于：

- 告诉编程模型准确的输入、输出格式；
- 驱动固定的 `test_solution.py` 执行 pytest；
- 为最终 Reviewer 提供测试覆盖信息。

## 使用流程

1. 用户输入题目。
2. 用户填写测试输入输出，或点击“AI 生成”。
3. 系统保存 `test_cases.json`，并生成固定 pytest 测试脚本。
4. 编程模型读取题目与 `test_cases.json`，编写 `solution.py`。
5. 本地环境执行 Bash 命令和 pytest。
6. 测试失败时，输出反馈给编程模型继续修改。
7. 本地测试通过后，Reviewer 分析算法、复杂度、边界情况和潜在风险。
8. 前端实时展示代码、命令输出、测试结果、运行轨迹和评审。

## 最终结果

每次运行应产生：

- `solution.py`：最终题解；
- `test_cases.json`：权威输入输出用例；
- `test_solution.py`：读取权威用例的固定测试脚本；
- `trajectory.json`：模型消息、动作和执行结果；
- `review.json`：最终评审。

本地测试通过只表示通过当前用例，不代表保证通过在线判题的隐藏测试。
